# 08 — Integrations, Excel, packs, collaboration and AI

## Data import and reconciliation
V1 CSV: user-selected local file; explicitly declare delimiter, quoting, encoding, date/decimal locale, header mapping, account/entity/period IDs, debit-credit or signed convention, currency and batch ID. Preview schema, duplicates, unknown members, invalid amount/date and unbalanced journals. Show errors/counts/totals by period/currency and mapping; reconcile source/import totals; rejected rows traceable. Store source digest, row reference, mapping version, operator/time and reconciliation. Never infer ambiguous date/currency. Enforce limits. Strict all-or-nothing initially.

Later connectors: staged adapters per driver/version, incremental watermark, retry/idempotency, credential storage, timeouts, drift/errors, endpoint allowlist and reconciliation. A server refresh requires connectivity to that server even without internet. Check ODBC/JDBC/SAP driver, bitness, DLL, redistribution and entitlement. Manual CSV fallback. No outbound connection without configuration.

## Excel contract
V1 includes the native Excel add-in specified in `11-uae-excel-v1.md` and generates `.xlsx` reports with values, simple supported styles and metadata; CSV optional. Publish limits/test matrix. Never overwrite source workbooks; future import handles only documented data and mapped formulas, writes a new project/file; unsupported content stops or is explicitly reviewed. No promise of full formula, formatting, chart, external-link, macro, Power Query, pivot or custom XML fidelity. POI has unsupported formulas and streaming limits; cached results can be stale. Disable macro execution; preserve only what is tested and disclosed.

Required native Excel V1 must first pass a separate proof: supported Office editions/bitness; Rust COM/XLL interface, registration/security/signing, batching and calculation/reentrancy. Conventional VSTO requires .NET/C# or VB, conflicting with five-language constraint unless approved. Ribbon COM add-in and XLL worksheet function are different components, not an automatic TypeScript/Rust bridge. Office.js needs verified offline cold start, hosting, trusted manifest and supported builds; browser cache is not a guarantee. Write-back must be explicit, authorized, revision-checked, previewed, batched/idempotent and audited; never silently write inside a UDF.

## Packs
Manifest: pack ID/version, min/max platform and schema versions, signer, dependencies, supported locales/jurisdictions/effective dates, license, sensitivity, checksums. Content: stable IDs, dimensions, dictionary, DSL, KPI definitions, synthetic samples, UI presets and tests. Verify signature/integrity, validate schema, preview impact, record provenance, migrate/rollback; no arbitrary code. Review ID/formula conflicts and customizations. Regulated packs need professional owner, sourced effective dates and review; XBRL taxonomies/filing rules maintained separately. A generic rules engine does not deliver complete GAAP/IFRS/tax correctness.

## Branching and collaboration
V1 branches share revision base and typed deltas, not raw Git files. Three-way compare base/current/branch. Conflicting coordinate, formula, mapping or hierarchy edits require human resolution, financial-impact preview and audited new revision. Approval may lock revision; local solo approval is not independent identity control. Define retention and permissions.

Future: encrypted manual exchange/diff first; consider authoritative LAN service with authenticated users, permissions, durable history and expected revisions. Define certificates, pairing/trust, revocation/device loss, stale offline access, conflicts/recovery. CRDTs only for genuinely commutative data such as comments, not automatic merge of approved finance assumptions. Distributed Erlang/mDNS add discovery/security complexity and are not default. Cloud sync separately opt-in and needs infrastructure/end-to-end encryption/key-sharing design.

## Optional local AI (future)
Off by default; deterministic core never depends on model. Separately acquired signed pack lists license, hash, format, resource needs and tested runtime/hardware; no automatic download. Test WinML/ONNX CPU/hardware providers on real Windows versions, GPUs/NPUs, operators and quantization. Memory = weights + runtime + context/cache; no universal 4 GB claim. Disclose slow CPU fallback.

Natural language → formula proposal only: compile/type-check, preview impact, human explicitly commits. Commentary cites authorized values/DAG/source; deterministic variance calculated first. AI cannot establish causal explanations without evidence. Treat imported text as untrusted prompt injection, restrict context by permissions and deny model-driven shell/network/write. User approves financial changes; record model/version/provenance and retention policy. Evaluate redacted fixtures for numeric accuracy, unsupported cases, privacy and hallucination; refuse unverifiable claims. Anomaly models are separately versioned and tested.
