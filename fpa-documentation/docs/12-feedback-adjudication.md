# 12 — Adjudication of AI-model feedback

**Status:** Draft · Reviewed 18 November 2026. The other AI responses are brainstorming inputs, not specifications or verified facts. This register prevents an implementation agent from copying conflicting claims. Chosen direction is provisional unless user confirmed or an ADR is approved.

## Adopt / investigate / reject
| Recommendation | Disposition | Reason |
|---|---|---|
| Rust hub; optional, replaceable sidecars | **Adopt as proposal** | Single authority/limited boundaries simplify solo build. Five languages remain part of vision, not an artificial V1 requirement unless user decides. A Rust fallback is not free: implement only required paths and document gaps. |
| Child stdio framed Protobuf | **Preferred spike** | Natural inherited channel, small control messages and fewer listeners; validate framing/EOF/backpressure, child stdout noise and crashes on each runtime. Excel is independently launched and needs different transport. Never record finance messages without explicit consent/redaction. |
| Named-pipe Protobuf / loopback | **Investigate fallback** | Native Windows named pipes or authenticated loopback where needed. ACL/PID checks and same-user auth have limits; code paths/protocol require threat review. No blanket assertion about library support or automatic firewall rule/admin. |
| Reference interpreter + differential/property tests | **Adopt as priority** | Small independent decimal-based interpreter using approved semantics; compare supported cases and error types. Do not let both systems share a flawed oracle specification. SME examples and Excel checks remain independent; no invented 80% bug-detection rate. |
| SCD2, non-additive measures, audit, exact allocation and backtesting | **Accept as roadmap/spec requirements** | Useful. V1 includes correct stock/flow aggregation; effective dates/allocations/backtesting are scoped to a pilot-specific approved need rather than hundreds of untested P0 items. Largest remainder needs signed amounts/tie-breaking and negative-weight policy specified. |
| UI grid spike | **Adopt** | Compare libraries/license/editing/accessibility and usable screen-reader behavior before custom Canvas/WebGL. An ARIA mirror isn't automatically accessible. |
| Excel XLL in V1 | **Confirmed outcome, implementation candidate** | Offline native add-in is user requirement; Rust XLL needs real Office ABI/security/command spike. UDFs read only; explicit command handles write-back. No forced language exception without owner approval. |
| Surgical OOXML patching with Tier A lossless guarantee | **Reject blanket guarantee** | Minimally scoped patching may preserve bytes of untouched parts, but relationships, signatures, formula caches and semantic fidelity remain hard; independently test each operation and refuse/warn on unsupported content. No arbitrary workbook round-trip in V1 by assumption. |
| Unencrypted disposable DuckDB cache | **Reject for confidential data** | Rebuildable data remains sensitive on disk. Encrypt cache, WAL and spill or use a verified encrypted volume; deletion isn't a confidentiality control. DuckDB docs describe encryption; version/config must be tested. |
| `WaitOnAddress` for cross-process shared-memory wakeup | **Reject** | Microsoft documents WakeByAddress* wakes only threads in the same process. Use suitable interprocess synchronization if a mapping is ever justified. |
| All-money Decimal128(38,6), all rates f64 | **Not approved** | Explicit scales/range/overflow/conversions need domain requirements. Fixed-point rounding still matters for multiplication/division. Binary floating rates may contaminate finance calculations; use decimal for financial rates and floats only where approved for stats. SIMD is not guaranteed for i128. |
| Global bit-identical results on all machines, floats/statistics | **Reject as unproved** | Define exact reproducibility within named builds/architectures and algorithms; deterministic fixed-point is tractable, float math libraries/CPU/reduction behavior vary. Test supported devices. |
| Always-balanced BS, direct CF = indirect CF on every edit | **Reject as universal invariant** | Drafts/unmapped data may be imbalanced; detect and block approved reports, not hide with a plug. Direct/indirect CF equality is valid only where definitions, population and reconciliation assumptions align. |
| FX round-trip within tolerance | **Conditional only** | Different rates/spreads/rounding, CTA and transaction vs translation differences invalidate a universal invariant. Test specific convention and time/rate. |
| Model 2 DSO cash collection formula | **Reject** | `Revenue × (1−DSO/days)` can be negative when DSO exceeds period days; it ignores timing/aging and isn't universal. Use reviewed aging/collection curves later. |
| Model 2 PVM formula | **Reject pending independent spec** | Example: budget A 50×10, B 50×20 = 1,500; actual A 80×12, B 20×22 = 1,400. Change = −100; proposed volume = 0, price = +200, mix = −150, total +50 (before FX). It does not reconcile. Build a documented convention and golden cases including new/discontinued items. |
| Average-balance interest eliminates most circularities | **Reject as universal** | If closing debt depends on interest/cash, average balance can itself be circular. Provide a solver or explicit non-circular convention only when defined. |
| Model 2 CFP/SOX claims and 100% compliance | **Reject** | Decimal and double entry alone don't certify SOX or account for incomplete inputs, accounting policy and exceptions. No self-certification. |
| AI numeric token validator makes hallucination impossible | **Reject** | Existing numbers can be combined/misattributed, units or causality can be wrong, and representations vary. Use deterministic facts and human review; measure failure rates. |
| LLM grammar guarantees valid references/correct finance | **Reject as universal** | Grammar can restrict syntax; names, dimension semantics, data access and accounting correctness still need independent validation. |
| CRDT financial last-write-wins / OTP distribution | **Reject for V1** | Single user and explicit semantic conflict handling; no distributed financial merges. Future collaboration requires separate authenticated architecture and review. |
| Hard-coded RAM/startup/GB/s/12–15 month solo deadline | **Reject as facts** | Hardware, models, runtime, team hours and complexity unverified. Establish baselines and stage gates; no schedule guarantee. |
| JDK 21/25 fixed jlink size/startup/GC claims | **Unverified** | Check selected version, libraries, license, feature support and Windows behavior; benchmark. Do not assume every Java library works in a small runtime. |
| MSIX impossible for Excel | **Not established** | MSIX capabilities/registration options differ; investigate. Prefer normal MSI/EXE initially, based on actual compatibility, not categorical assertion. |
| PID/path + token means strong same-user IPC isolation | **Reject as absolute** | Same-user malware/admin can impersonate, inspect or alter accessible resources; ACL/auth/handles reduce risk but are not a hardened sandbox. |
| Auto-kill processes based on executable path/marker | **Reject** | PID reuse or stale/malicious markers can kill an unrelated process. Job Object handles and verified managed process handles only; no broad startup kill sweep. |
| Graph/function registry generating everything automatically | **Investigate later** | Registry can generate docs/contracts after behavior specified; metadata cannot replace evaluator and independently authored tests. |
| WASM plugins, cloud, 9 packs | **Defer** | No security/maintenance ROI until V1 and actual demand. |

## Documentation precedence
This register and v0.2 accepted user scope supersede earlier draft wording. In particular, a mandatory native Excel V1 is not a later feature. Underlying accounting, architecture and legal assumptions remain subject to approval. If any future text contradicts this, stop and open a change request.
