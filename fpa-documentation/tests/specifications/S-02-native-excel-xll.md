# S-02 — Native Office 2021 x64 XLL feasibility: test specification

> **Correction:** The stack, thresholds, pre-approvals and spike order below came from another AI as recommendations, not from the owner. This draft is unapproved research; no spike is authorized or has run. Conditional C/C++ use is not pre-approved.

**Status:** Draft authored; spike sequence is a proposal, not owner-authorized. **NOT RUN.** First gate. Pure Rust C-ABI first; conditional thin C/C++ fallback per [ADR-001](../../decisions/ADR-001-v1-lean-local-core.md). No actual API, XLL, daemon, Office build or test harness is claimed to exist.

## Objective and boundaries
Prove a locally signed, native x64 XLL can load under allowed Office policy, provide read-only revision-bound synthetic values, safely handle Excel ABI/memory/threads, and support a separately invoked preview/commit command via a single per-workspace Rust authority. No real company data, VBA execution, external network, weakened macro settings or broad trusted locations. The scope is a disposable feasibility fixture, not production finance functionality.

**External AI proposed gate, not approved:** zero crashes across 1,000 recalculations and process restarts; process/UI hangs, access violations, memory corruptions, silent wrong values, duplicate mutations or leaked ownership count as failure even without a crash. Because the external recommendation did not separately state the restart count, require **at least 1,000 recalculation cycles plus at least 100 complete restart cycles** as a provisional minimum for this plan, not as a reinterpretation of the proposed gate, covering Excel and daemon restarts; seek owner confirmation whether 1,000 restarts are also required before signing off. An interrupted/incomplete run is NOT PASSED. At least one cycle exercises each startup order and multi-client contention. Record Excel calculation mode and actual recalc counts, not only elapsed loops.

## Prerequisites and setup
- Owner-provided Windows 11 x64 + Excel Office 2021 x64, exact OS/Office edition/build, update channel, SKU and tenant policies recorded. Corporate deployment approval and narrowly scoped trusted folder + signed XLL/installer; no policy changes without IT authorization.
- Disconnect network and confirm offline operation after all prereqs installed; independently document certificate chain/trust and offline validation behavior. Record MSVC/Rust/SDK versions, architecture, build flags, reproducible source revision, hashes and license/SBOM. The external AI suggested Microsoft Excel C API SDK 2013+ for a conditional shim; verify acquisition/licensing/build compatibility.
- Disposable synthetic workspace with registered deterministic values and revisions, no secrets; approved test harness, instrumented logs excluding financial content. Capture event logs/Excel crash dumps in secure test environment. Collect process counts, handle counts and stable-memory trends; define baseline/tolerances before run, investigate monotonic leak rather than inventing zero-noise limits.
- Create a written test contract for calculation/event triggering, native API lifecycle and Excel command surface. The Ribbon/Add-in command mechanism itself is unproven for a pure XLL; treat as a separate feasibility requirement, not assumed available.

## Planned cases
| ID | Procedure | Pass condition |
|---|---|---|
| XLL-01 Load | Install signed XLL in approved location, open Excel offline. | Load succeeds without reducing Trust Center protections; record certificate and host build. |
| XLL-02 Registration | Register test UDF, return Unicode string, blank, errors, array and numeric boundary values. | Correct type/value or documented safe error; no invalid pointers/UTF-16 corruption. |
| XLL-03 Ownership | Exercise allocation, return/free of strings/arrays and unload, repeated under memory instrumentation. | Matched ownership/free path, no invalid free/use-after-free or attributable monotonic leaks. Include `xlAutoFree12` where applicable. |
| XLL-04 Threading | Evaluate read-only UDFs with Excel multi-threaded recalc on and off; stress simultaneous values and parallel clients. | Results match pinned revisions; no shared mutable return buffers/data races; only register thread-safe when tested and allowed APIs are used. |
| XLL-05 Lifecycle | Excel-first, desktop-first, simultaneous launch, daemon crash, Excel restart, desktop exit with Excel open, logoff and reattach. | One authority per workspace, bounded startup/timeout, proper recovery and no unsafe duplicate writer or corrupted state. |
| XLL-06 Multi-client | Two workbooks and, where supported, two Excel instances for same workspace; competing workspace selections. | Correct revision/workspace identity; no data mix or writer duplication. |
| XLL-07 Staleness | Get revision R, advance to R+1, disconnect daemon, reopen workbook with XLL blocked/disabled. | During active evaluation staleness/error is visible and no stale result is falsely marked current. Document saved caches may remain visible if add-in unavailable; no impossible promise to clear them. |
| XLL-08 Precision | Test exact text `0.1000`, `0.0001`, negative, rounding ties, boundaries around 15 significant digits, >15 digits, IDs, missing and errors. | Scaled integer transport only where safe; decimal numeric outputs disclose approximation/round-trip policy; values unsuitable for approved numeric contract become exact text or explicit error, never silently truncated. |
| XLL-09 Write command | Preview selected synthetic range, cancel, confirm, repeat same key/same payload, same key/different payload, stale revision and crash after commit before response. | No UDF mutation; cancel/no preview writes nothing; confirmed transaction atomic and audited; identical retry returns original outcome; changed request conflicts; unknown commit resolved from persisted status. |
| XLL-10 Security | Test another Windows user, remote client attempt, unauthorized pipe, invalid frame, oversized input, named-object collision and timeout. | Unauthorized/remote access rejected; bounded failures; current-user ACL alone not claimed to defeat malicious same-user processes. |
| XLL-11 Soak | At least 1,000 verified recalcs plus planned restart cycles with varied outputs/workbooks and both calc modes. | Zero crashes/hangs/corruption or silent wrong results; logs, invocation counts, memory/handle trends retained. |
| XLL-12 Offline trust/recovery | Block network, deny unapproved certificates/locations, try disabled add-in and unavailable daemon. | Fail clearly without bypassing corporate policy or network; failure states and saved-workbook residual risk recorded. |

## Evidence, gate and fallback
Record tester/date, source commit & binary hashes, build and library versions, certificate provenance/policy, OS/Office details, hardware, commands/procedure, number of actual recalc invocations and restarts, measurements, individual case results, logs, crash artifacts and unresolved issues. A pass requires every applicable case and an approved threshold; any skipped test is unrun, not pass. Measure UI responsiveness and command interaction without prescribing unsupported timing.

If pure Rust fails due to ABI/lifetime/thread instability, open a documented issue, preserve artifacts and seek explicit owner approval before considering the proposed <500-line C/C++ glue fallback. Rerun the **entire** S-02 matrix, not only the failed case. Include source line-count method and review that no financial/business logic exists in the shim. An unfixable corporate policy, missing signing certificate, unavailable Office 2021 or unclear command surface is **BLOCKED**, not pass; workaround requires owner/IT decision.
